> 8. **新增 TC-EMP-012 身份绑定**（token 里的身份为准，不能靠传参冒充）。
> 9. **新增 TC-CS-012 多轮指代**、**TC-CS-013 重复报名去重**。

> 11. 其余为措辞与判定口径细化（便于"过/不过"二值判定）。

### 0.4 通用判定口径

- **通过**：返回中文话术 + 业务数据落库（可在查询接口或 `/admin` 复现），两者都对才算过。
- **状态码**：参数非法 → `400`；资源不存在 → `404`；字段校验失败 → `422`；未登录 → `401`；有登录但无权限 → `403`。
- **不得编造**：费用、政策、报名、名额、签证、永居等关键数字必须能在知识库原文找到；找不到要明确说"知识库中暂无该项信息"。
- **不得越权写**：任何"查询/拒绝"类输入，结束后不得新增/修改任何业务表（GC 时用 `select count(*)` 对比前后）。
- 每条用例记录：**实际结果 / 通过与否 / 证据（SQL 结果或截图）**。

## 1. 模块一：用户画像研判（共享工具）FR-001 ~ FR-005

**接口**：`POST /api/agent/profile-evaluate`

### TC-PROF-001 全字段结构化画像（FR-001 正常路径）
- **优先级**：P0
- **输入**：`{"name":"张三","age":19,"education":"高中","intent":"升学","family":"家里很有钱"}`
- **预期**：
  1. 优先采用结构化字段，不触发正则兜底；
  2. 返回归一化画像（`education="高中"`、`intent="升学"`）；
  3. `matches` 命中「0.5/1+2 新加坡定向培养本科班」，`best_match` 含项目名 + 理由 + 分值（示例 93，可浮动，但不得为 0）。

### TC-PROF-002 仅 raw_text 走正则兜底（FR-001 降级）
- **优先级**：P0
- **输入**：`{"raw_text":"姓名 张三 性别 男 年龄 19岁 家里很有钱"}`
- **预期**：能抽出 `age=19`；`education` 抽不到就留空或原样，**不得**编造"高中"；`profile / matches / best_match / summary` 四个 key 都在。

### TC-PROF-003 学历语境识别：目标学历 ≠ 当前学历（FR-001 业务规则）
- **优先级**：P0（最易错点）
- **输入**（4 组逐个测）
  1. `"我19岁，高中刚毕业，想快点拿本科学历"`
  2. `"我是专科毕业，想读本科"`
  3. `"我现在高二在读"`
  4. `"本科毕业了，想读个硕士"`
- **预期**：① `education=高中` → 0.5/1+2；② `专科` → 一年制专升本；③ `高中`（高二归高中桶）→ 0.5/1+2；④ `本科` → 一年制本升硕。

### TC-PROF-004 学历归一化优先级（FR-002）
- **优先级**：P0
- **输入**（逐个）：`研究生 / 硕士 / 本科 / 大专 / 专科 / 中职 / 技校 / 高中 / 初中`，外加 `中一 / 学历不详`
- **预期**：前九个依次归一为 硕士 / 硕士 / 本科 / 专科 / 专科 / 中职技校 / 中职技校 / 高中 / 初中；词表外**原样返回**，不硬塞进 6 个桶。
- **判定要点**：优先级必须严格 **硕士→本科→专科→中职技校→高中→初中**。

### TC-PROF-005 意向归一化（FR-003）
- **优先级**：P0
- **输入**：`想找工作 / 想就业 / 想移民 / 想拿永居 / 想升学 / 想提升学历 / 想出国留学 / 想读本科 / 随便看看`
- **预期**：就业 / 就业 / 移民 / 移民 / 升学 / 升学 / 升学 / 升学；`随便看看` 无法归一（留空或原样，不得乱分类）。

### TC-PROF-006 学历→项目池匹配（FR-004 核心）
- **优先级**：P0
- **输入**（5 组）
  1. `{"age":15,"education":"初中","intent":"升学"}`
  2. `{"age":17,"education":"高中","intent":"升学"}`
  3. `{"age":21,"education":"专科","intent":"升学"}`
  4. `{"age":23,"education":"本科","intent":"升学"}`
  5. `{"age":17,"education":"中职技校","intent":"就业"}`
- **预期**：① 2+2（可含 2+2+1）；② 0.5/1+2；③ 一年制专升本；④ 一年制本升硕；⑤ 6+6 酒店运营大专就业班 和/或 9+6 航空运营大专就业班。

### TC-PROF-007 德国双元制三个硬条件（FR-004，必须是"与"）
- **优先级**：P0（规则做错会直接把不合格学员推进项目）
- **输入**（4 组对照）
  1. `{"age":25,"education":"高中","intent":"就业","language":"德语B1","hands_on":"强"}` → **命中**
  2. `{"age":17,"education":"高中","intent":"就业","language":"德语B1","hands_on":"强"}` → 不命中（年龄 <18）
  3. `{"age":30,"education":"高中","intent":"就业","language":"无","hands_on":"强"}` → 不命中（无德语）
  4. `{"age":30,"education":"高中","intent":"就业","language":"德语B1","hands_on":"弱"}` → 不命中（动手能力弱）
- **预期**：
  1. 第 1 组必须命中，且**要确认命中的是「德国双元制职业教育」（id=8）**，不是「6+6 酒店运营大专就业班」或「9+6 航空运营大专就业班」——三者都含"就业/大专"，是误判高发点；
  2. 第 2/3/4 组 `matches` 中不得出现任何一条"双元制"，且话术要说明缺哪个条件（年龄/语言/动手能力）。

### TC-PROF-008 无匹配时不得编造（FR-004 / 9.6）
- **优先级**：P0
- **输入**：`{"age":45,"education":"硕士","intent":"移民","language":"无"}`
- **预期**：`matches` 为空或明确"未找到匹配项目"，`best_match=null`；不得凭空推荐；应提示补充信息或转人工。

### TC-PROF-009 匹配度加分与上限（FR-005）
- **优先级**：P1
- **输入**（3 组）：① 升学画像命中本科/本硕 → +3；② 就业画像命中就业班/双元制 → +5；③ 移民画像命中双元制 → +5
- **预期**：同画像下"意向对口"分值高于"不对口"；所有分值 **≤100**；列表**按分值降序**；同名项目**不重复出现**。

### TC-PROF-010 输出结构契约
- **优先级**：P1
- **预期**：含 `profile / matches[]（project, reason, score）/ best_match / summary`；`summary` 形如「张三（高中）推荐【0.5/1+2 新加坡定向培养本科班】，匹配度 93 分。」

## 2. 模块二：留学生智能管家（学生侧）FR-006 ~ FR-015

### TC-STU-001 请假：自然语言解析（FR-006）
- **优先级**：P0
- **接口**：`POST /api/agent/leave-apply`，body `{"student_id":1,"reason":"<原文>"}`
- **输入**（逐个，**保留原文**）
  1. `"我明天要请假一天，家里有事"`
  2. `"我今天下午请假半天"`
  3. `"后天请假三天，去医院"`
  4. `"2026-11-20 到 2026-11-22 请假，回家"`
  5. `"请两天假"`
- **预期**：① 明天/1 天；② 今天/0.5 天；③ 后天/3 天；④ 直接用明确日期区间；⑤ 2 天（中文"两"能识别）。
  全部情况 `status=待审批`，且能被 TC-STU-002 查到。

### TC-STU-002 请假查询过滤（FR-007）
- **优先级**：P1
- **接口**：`GET /api/agent/leave-list?student_id=1[&status=待审批]`
- **输入**：`student_id=1` → `student_id=1&status=待审批` → `student_id=2` → `status=已通过`
- **预期**：前两组返回 TC-STU-001 记录且第二组只含待审批；`student_id=2` 返回空列表（不报错、不串号）；第四组只返已通过。

### TC-STU-003 请假审批通过/驳回（FR-008）
- **优先级**：P0
- **接口**：`PUT /api/agent/leave-approve/{id}`，body `{"approver_id":3,"approved":true/false}`
- **预期**：状态正确落库（用 leave-list 复查）；返回"已通过/已驳回"话术；`approve_time`、`approver_id` 同时被写入。

### TC-STU-004 请假审批-资源不存在
- **优先级**：P0
- **输入**：`PUT /api/agent/leave-approve/9999`
- **预期**：`404` + "请假申请不存在"；不得静默成功、不得新建记录。

### TC-STU-005 情绪评估四档（FR-009）
- **优先级**：P0（分值直接决定预警，必须逐档验）
- **接口**：`POST /api/agent/emotion-evaluate`，body `{"student_id":1,"text":"..."}`
- **输入**（每档独立提交，便于核对）
  1. `"最近压力好大，感觉活不下去了"` → 90 / 高危
  2. `"最近总失眠，很焦虑，有点抑郁"` → 55 / 关注
  3. `"今天特别开心，考试过了！"` → 15 / 正常
  4. `"今天正常上课"` → 20 / 平稳
- **预期**：`emotion_tag`、`emotion_score`、`risk_level` 与档位一致；`student_psych_profile` 已 upsert（最新标签/分值/最近交互时间）。

### TC-STU-006 高危预警触发与通知（FR-011 / ACC-002）
- **优先级**：P0（验收硬指标）
- **前置**：`student_id=1` 情绪分值 <70
- **输入**：`{"student_id":1,"text":"最近压力好大，感觉活不下去了"}`
- **预期**：① `alerted=true` 且有 `alert_id`；② 话术含"已通知班主任关注"（或等价）；③ `student_psych_alert` 新增一条（触发原因 / risk_level=高 / status=未处理 / teacher_id=3）；④ `/admin` 心理预警表可见。

### TC-STU-007 预警阈值边界（FR-011 / 9.2）

## 5. 模块五：系统公共 FR-029 ~ FR-031

### 5.1 TC-SYS-000 【新增】登录与角色权限矩阵（12.2，本项目最高风险区）

- **优先级**：P0
- **步骤**：`POST /api/auth/login`，用 §0.2 的 14 个账号逐个登录，检查返回的 `perms` 与页面可见入口。

| 账号 | 期望可见 | 期望不可见 |
|---|---|---|
| admin（王主任） | 全部 + **数据后台 `/admin`** | — |
| emp005（郑主任/领导） | 全部业务数据（跨组）、审批、**数据后台（只读）** | — |
| emp001（李老师） | 自己名下客户、自己学生的请假/成绩/预警、审批自己学生 | 别的班主任的学生、`/admin` |
| emp004（孙老师） | 同上（范围是自己学生） | 赵敏/李老师的学生 |
| emp006（陈老师） | 同上（无下属学生 → 列表为空，不报错） | 其他人的数据 |
| stu001（张三） | 本人请假/成绩/情绪/反馈 | 审批入口、客户线索、别人成绩 |
| parent001（陈女士） | 仅绑定学生（张三）的信息 | 其他学生、员工功能 |

- **预期**：
  1. 密码错 → `401`；账号不存在 → `401`（不区分，防枚举）；
  2. 学生 token 访问 `/admin` 或 `/api/admin/tables` → **403**；无 token → **401**；
     （注：系统的角色矩阵把"管理员"和"领导"都归为 admin 级，因此郑主任可进只读后台，这是设计如此，不是越权。）
  3. 前端 `数据后台` 链接只对 admin 显示（`state.perms.admin` 为真时才 `hidden=false`）；
  4. 同一账号换设备/重登，权限不串。

### TC-SYS-001 对话记录沉淀（FR-029）
- **优先级**：P2

### TC-SYS-002 健康检查（FR-030）
