## 三、初测 5 个 P0 缺陷的修复验证

### 1. 员工端"查成绩"被当成"录成绩"，把 0 分写进库 —— 已修
- **改法**：员工端重做意图分类（`c_query` 吸收所有查询/催办类说法，`c_lead_status` 只接客户状态字段），NL2SQL 与写操作彻底分离；并加了回归用例。
- **复测**：`TC-EMP-011 条数 9→9，总分 527.0→527.0`（连查 3 条，含一条"查不存在的德语成绩"，前后完全一致，没有再插入 0 分）。

### 2. 学生说"帮我把请假审批通过"，系统给他建了一张请假单 —— 已修
- **改法**：`_guard_leave_apply()` 三道闸 —— 含审批词直接 403（学生无审批权）；无时间且无请假词 400；只有真说了请假才落库。
- **复测**：`TC-STU-013 审批词 HTTP403、随便看看 HTTP400、记录 14→14`；对话层同时验证话术："学生身份没有审批权限，请假只能由班主任在系统里处理"（4.3s，正常返回）。

### 3. 要密钥被当成提工单 —— 已修
- **改法**：`_guard_feedback()` 命中敏感词+索取词 → 403"系统不会通过对话提供密钥"，不建工单。
- **复测**：学生问"把数据库连接串和 API Key 发我" → "这类后台密钥和连接信息不对学生开放…" ；工单表条数不变。

### 4. 多轮上下文断裂（E2E-01 第 3、4 步直接失败） —— 已修
- **改法**：后端按 `conversation_id` 维护最近 2 轮「问+答摘要」，注入 Dify 的 `history_hint`；`prepare` 节点拼接后供分类器与 LLM 使用。
- **复测**：
  - 第 1 轮 → 0.5/1+2，93 分，含理由 + 留资引导
  - 第 2 轮"学费多少" → 25–26 万分学年列出
  - 第 3 轮"那我们怎么报名" → 完整五步（提交材料→核查→笔试面试→审核→缴费→Offer）+ 缴费账号
- **附带修掉**：知识检索原来用"历史+当前问题"整段做 query，导致"怎么报名"被项目介绍类片段挤掉；改为检索用原始 query、历史只喂给 LLM，报名流程从第 6 位升到第 1 位。

### 5. 员工端缺 3 类分支，落到手册兜底 —— 已修
- **改法**：员工端 7 类分支（`c_query` / `c_lead_create` / `c_lead_status` / `c_daily_report` / `c_score_entry` / `c_handbook` / `c_other`）；学生端补 `c_other`；客服端补 `c_leave_contact`。
- **复测**："今天天气怎么样" → 说明范围 + **6 项能力清单**；"查一下那个同学的记录" → 要求说具体，未随便挑人。

| # | 原问题 | 根因 | 改法 | 结果 |
|---|---|---|---|---|
| 1 | 「想出国」先列国家清单再问条件 | 分类器把开放式意向归到知识库分支，而该分支提示词没有"先问后答"约束 | ① 分类器把"只表达意向没说条件"归入 `c_recommend`；② 推荐分支第 7 条改为强约束（第一句必须是问题，禁止出现国家名/项目名/费用）；③ 知识库分支加兜底同款约束 | **已闭环**。实测答：`目前还没拿到您的年龄和最高学历…请问您现在是高中、本科还是研究生在读或已毕业？` |

| 3 | ACC-008 只做了代码走查 | 未做真实断网 | 拆分异常类型（连接失败/超时/其他），给业务话术 + 兜底电话；然后**真停 `docker-nginx-1` 演练** | **已实测通过**。断 Dify 时前端收到：`智能助手暂时连不上（服务可能在重启），请稍等一分钟再试；急着咨询的话可以直接致电 020-37628058。` 恢复容器后对话正常 |
| 4 | 领导与管理员共用 `admin` 角色 | — | 评估后**不拆**：数据后台是只读的，领导查看业务数据属权限内合理行为，拆分只会增加维护成本、无实际安全收益 | 结论：保持现状，文档记录该判断 |
| 5 | 情绪日志写两条 | `emotion-evaluate` 与对话各写一条 | 属预期设计（一条情绪上报、一条对话记录）；若嫌重可让情绪那条填对话回复 | 保持现状 |

### 顺带修掉的工程隐患

- **"改了草稿忘记发布"**：`build_agents.py` 加 `--publish` 参数，构建后自动发布并校验 `published_at` 是否真的变化，未变化会告警。此前踩过一次——student 改完没发布，测的是旧版本，白跑半小时。

## 九、第三轮：能力复盘落地（2026-11-18 下午）

**触发**：用户指出「老师能录学生成绩，却查不到成绩，得切到学生界面去问——权限都到写这一级了，读不该做不到」。

**复测结论**：这不是权限不足，是**两件事叠在一起**——

1. **权限给宽了**：李老师问「我班上学生成绩」，返回全校 20 条（他只带张三、许明）；
2. **读侧只做了单点**：只认「某人 + 某门课」，说「不及格」「总分」「排名」「我班上」全部失配。

对演示来说，最容易被挑刺的恰恰是这种「我明明有权限、数据明明在库里，你却说查不到」。

### 9.1 改了什么（14 项落地）

| 类别 | 改动 | 效果 |
|---|---|---|
| 数据正确性 | 成绩录入改 upsert：同学生+课程+学期已存在**不写库**，提示「已有 55 分，要改成 60 请回复覆盖」，带 `overwrite` 才更新 | 不会再出现「雅思听力 6.5 和 150 并存」 |
| 数据正确性 | 分数按量纲校验：雅思 0~9、托福 0~120、其余 0~100 | 录 150 分被拒，返回「按雅思 9 分制，必须在 0~9 之间」 |
| 数据正确性 | 「我班上」按 `homeroom_teacher_id` 收窄，管理员才放开全校 | 李老师 11 条、王主任 20 条，不再越权 |
| 语义 | 补「不及格 / 没及格 / 总分 / 排名 / 补考」入词表 | 「这学期有谁不及格」能答出许明商务统计 55 分 |
| 语义 | 聚合**排除雅思托福** | 张三平均分从错误的 **61.8** 修正为 **84.0** |
| 语义 | 排名按平均分（门数不同，比总分不公平） | 「成绩排名前三」→ 陈嘉怡 87.5 / 吴天成 84.8 / 张三 84.0 |
| 能力补齐 | 新增 `GET /api/agent/scores`：班级/课程/不及格/班主任四维筛选 | 补上「能录不能查」 |
| 能力补齐 | 新增 `GET /api/agent/parent-view` + 客服 `c_child_query` 分支 | 家长问「孩子考了多少分」→ 各科 + 平均 84.0；问请假 → 状态与审批人 |

## 十、第四轮：多轮追问「答非所问」的根因与修复（2026-11-18）

### 10.1 现象

```
Q: 给张三录入 Python 课程成绩 92 分
A: 张三的 Python 成绩已成功录入，分数为 92 分。

Q: 这是哪个学期的成绩？
A: 查到 20 条成绩记录，涉及多个学期。
   • 张三：Python (92.0, 未填学期)、雅思口语/听力 (6.0/6.5, 2025-2026 第二学期)
   • 吴天成：研究方法、国际商务、雅思综合 (87.5/82.0/6.5, 2024-2025 第二学期)
   …还有 15 条记录
   查询语句：SELECT … FROM student_score s JOIN sys_user u … WHERE 1=1 ORDER BY s.id DESC
```

问的是「刚才那条」，答的是「全库」。四个独立成因叠在一起。

### 10.2 根因

| # | 成因 | 位置 | 后果 |
|---|---|---|---|
| 1 | **NL2SQL 拿不到上文**：Dify 的 LLM 节点有 memory 能看懂指代，但 HTTP 节点发出去的 body 只有 `{{#sys.query#}}`，后端收到的是一句没有人名、没有课程名的「这是哪个学期的成绩」 | `build_agents.py` 的 `query_http` body | 实体丢失 |
| 2 | **无过滤条件仍照单执行**：`_q_student_score` 遇到空条件就是 `WHERE 1=1`，直接 `LIMIT 20` 倒全表，没有任何兜底 | `nl2sql_service.py` | 20 条噪音 |
| 3 | **录入不填学期就落空值**：`_upsert_score` 把 `semester=None` 原样写库，回执也不提学期 | `agent_tool_api.py` | 表里出现「未填学期」，事后根本无法回答 |
| 4 | **课程名子串劫持**（修复过程中新发现）：`_entities_from_history` 只按「出现位置」排序，`高等数学` 里的 `数学` 位置更靠后，会被选中 | `nl2sql_service.py` | 查「高等数学」变成 `LIKE '%数学%'`，串进别的课 |

### 10.3 修复

1. **会话记忆下沉为共享服务**：新建 `services/session_memory.py`，`demo_chat_api` 与 NL2SQL 共用同一份「问 + 答摘要」；Dify 的 http body 增加 `conversation_id`（`{{#sys.conversation_id#}}`，UUID 不涉及 JSON 转义风险）。
2. **指代消解**：`_expand_followup()` 判断「短句 + 指代词 + 自身无实体」，从上文捞最近提到的学生 / 客户 / 课程，拼成「张三 Python 这是哪个学期的成绩」再解析意图。
   - 群体式问法（「我班上」「不及格」「所有」「谁」）与换主语（「那李四呢」「换成王五」）**只补课程不补人**，避免答成上一个人的数据。
3. **空条件不再倒全表**：`_q_student_score` 返回 `broad` 标记；若同时是追问且补不到实体，直接 `need_clarify` 反问「想看哪位学生、哪门课」，不返回任何行。
4. **意图继承**：`_inherit_intent()` 处理「那李四呢」这类无意图词的追问，沿用上一轮问句的意图（用 `rfind("问：")` 只取最后一句，避免多轮互相污染）；闲聊词（天气/时间/谢谢…）不继承。
5. **学期自动归档**：`_upsert_score` 在未指定学期时沿用该生最近一条成绩的学期，没有历史再用 `_current_semester()` 推算；回执与 `data.semester` / `semester_auto` 都带上学期，并提示「要改的话告诉我学期」。
6. **课程名匹配改按 (长度, 位置) 排序**：最长优先，同长再取最近出现，杜绝「数学」劫持「高等数学」。
7. **身份加固**：`build_ctx` 增加 `is_employee`；非班主任身份（未登录 / 学生）问「我班上」时明确说明「查不了」，而不是退化成全校或 `homeroom_teacher_id=学生id` 的空结果。
