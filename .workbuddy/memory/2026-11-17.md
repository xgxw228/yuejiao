# 2026-11-17 粤教服务项目

## 在本地 Dify 中重建三个 Agent（已完成）

Dify 1.10.0 跑在 localhost:80，FastAPI 后端 localhost:8000（uvicorn --reload）。

### 关键操作路径（可复用）
- 控制台鉴权：POST /console/api/login 拿 cookie（access_token/refresh_token/csrf_token），
  后续请求必须同时带 Cookie + `X-CSRF-Token`，只带 Bearer 会 401。
- 改草稿：GET /apps/{id}/workflows/draft 取 hash → POST 同一路径带 `hash`（乐观锁，缺 hash 报
  draft_workflow_not_sync）。
- 发布：POST /apps/{id}/workflows/publish。
- 调试跑：POST /apps/{id}/advanced-chat/workflows/draft/run（chatflow 专用，workflow 模式用的是
  /workflows/draft/run，chat-messages 只支持 chat/agent-chat）。

### 踩过的坑
1. 变量引用必须写 `{{#sys.query#}}`，写成 `{{#start.sys.query#}}` 会被解析成 3 段路径而取不到值。
2. 开始节点的 default_value 只在节点失败降级时用，不会给输入变量兜底；后端必须自己容错空串。
3. question-classifier 别乱写 instruction，内置提示词要求输出 JSON{category_id}；
   自定义"只输出分类 id"会让解析报 `got invalid return object`。
4. deepseek-flash 是推理模型，思考过程会混进回复；LLM 润色节点改用 tongyi qwen-plus。
5. Dify 的 HTTP 请求走 ssrf_proxy:3128，`http_access allow localnet` 放行容器网段，
   host.docker.internal:8000 可达。

### 交付物
- backend/routers/agent_tool_api.py：21 个 Agent 工具接口（画像研判、情绪预警、请假、反馈、成绩、
  CRM、日报、NL2SQL、活动报名等），前缀 /api/agent。
- backend/services/：profile_match_engine（规则+评分）、emotion_engine（阈值分级）、leave_parser（口语时间解析）
- backend/seed.py / reset_demo_data.py：演示种子数据与脏数据清理
- .workbuddy/tmp/build_agents.py：三个 Agent 的图构建脚本（拓扑：开始→意图分类→工具→润色→回复）

### 已知限制
知识库是 economy 关键词索引，中文分词弱，「公司新人指南」在"新员工入职材料"类问题下召回不到，
员工侧制度分支会答"不确定"。建议把该文档单独建 high_quality 索引的库。

## 演示前端 + Dify 服务 API 接入（已完成）

### 链路
浏览器 http://127.0.0.1:8000/demo/ → 后端 /api/chat/stream（SSE 代理）→ Dify
http://localhost/v1/chat-messages → 工作流 → 后端 /api/agent/* 工具接口。

不让浏览器直连 Dify 的三个原因：nginx 不给 /v1 加 CORS、API Key 会暴露在前端 JS、
代理层可顺手把 Dify 的 SSE 事件裁剪成前端友好的 delta/node/done/error。

### 新增文件
- frontend/index.html：单文件演示控制台（三角色切换、流式输出、工具调用标签、
  耗时/tokens 计费、身份切换、快捷提问），自定义轻量 Markdown 渲染，无外部依赖
- backend/dify_agents.py：三个 app_id + API Key + 角色元数据（唯一配置入口）
- backend/routers/demo_chat_api.py：GET /api/chat/agents、POST /api/chat/stream
- main.py：挂载 StaticFiles 到 /demo，根路径 302 跳转

### 坑
1. main.py 里 mount 静态目录用了 os.path.isdir 守卫，目录后建时必须 touch main.py
   触发 reload，否则 /demo 一直 404。
2. 前端起始输入变量是 user_id(number) + *_name(text)，必须传 int，传字符串会被 Dify 拒。
3. Git Bash 里 curl -d 传中文会被转码破坏 JSON，测接口一律用 python urllib。
4. .workbuddy/tmp 下曾有 inspect.py 遮蔽标准库 inspect，导致 websockets 导入链报错。

### 验证方式
本地用 CDP（websockets 库 + Edge --remote-debugging-port）驱动无头浏览器截图，
脚本 .workbuddy/tmp/cdp_shot.py，比 playwright 轻，无需安装依赖。

## 员工制度知识库改为高质量语义索引（已完成）

### 起因
economy 关键词索引下「新员工入职要准备哪些材料」召回不到《公司新人指南》，
Agent 只能答「建议问行政同事」。

### 做法
1. 新建知识库 `员工制度手册`（id debc6ed5-1524-47ac-9431-45ecd8c25341），
   indexing_technique=high_quality，embedding=text-embedding-v3（tongyi）。
2. 内容不是重新上传 docx（原文件已不在磁盘），而是把旧库 7 个切片的内容
   规范化成结构化 Markdown（## 一级标题 / ### 二级 / 保留表格），
   去掉「。。」重复标点、把被拆行的 "1." 标题合并。
3. 切片分隔符用 `\n### `，max_tokens=300，overlap=40 → 35 个切片（原来 7 个，
   单个上千字导致语义被稀释）。
4. 员工侧 handbook_kb 节点改为只检索新库，top_k=5、score_threshold=0.5。
5. 制度问答提示词重写：人名/分机/电话/位置照抄原文，未覆盖时答
   「手册里没有这条，建议问行政同事（分机 8001）」。

### 关键发现
- create-by-text 在 **服务 API** 才有（/v1/datasets/{id}/document/create-by-text），
  console API 只有 upload_file 走 data_source 的那条路；服务 API 要 dataset key
  （POST /console/api/datasets/api-keys 生成，租户级通用）。
- 建库时 index technique 是 high_quality，但 embedding_model 不会跟着请求走，
  默认落成 multimodal-embedding-v1（多模态模型，文本检索很差）。
  必须 DELETE 文档 → PATCH /datasets/{id} 改 embedding_model → 重新建文档。
- hit-testing 接口可直接对比检索效果（POST /datasets/{id}/hit-testing），
  不用每次跑整条工作流，调参效率高很多。

### 效果
- 入职材料：完整答出身份证/毕业证/离职证明/社保卡/银行卡 + 复印件2份 + 
  学信网报告 + 设备清单
- 公司福利：健康保障/学习支持/弹性工作/员工活动 分条列出
- 健身房：07:00-22:00、提前15分钟预约、分机8021、瑜伽课时间 全对
- 报销流程：手册确实没有，诚实兜底（预期行为）

## 客服侧 + 学生侧知识库一并高质量化（已完成）

### 新库
`留学项目资料库`（id ef37795b-f4f8-47da-933f-739942b47692），high_quality + text-embedding-v3，
140 个切片。内容由 7 份旧文档合并清洗而来（29515 字）：
企业信息 / 中德精英人才共建计划 / 新加坡国际本硕升学计划 / 新加坡留学政策指南 /
德国留学政策指南 / 项目问答对 / 用户画像研判规则。

### 关键取舍
- **没有索引 wanmei 官网全文**：3 个 txt 合计 1060 万字，embedding 成本与切片数量都不可控，
  官网文案对「政策/费用/申请条件」类问题价值也低，改用企业信息.docx 覆盖公司介绍。
- 合并时把 `一、二、` 转 `### `、问答对的 `Q\tA` 转 `### Q\nA`、短行小标题转 `### `，
  分隔符用 `\n### `、max_tokens=400 → 64 个语义单元切出 140 片。
- 清洗规则里要排除「电话/邮箱/邮编/地址」这类短行，否则会被误判成标题把内容切断。

### 节点改动
- 客服 faq_kb → DS_PROJECT，top_k=3，threshold=0.5
- 学生 kb_retrieval → DS_PROJECT，top_k=3，threshold=0.5
- 三个应用全部重新发布

### 意图分类边界修正（客服）
原 c_project_query 里写了「什么条件能报」，导致「新加坡本科的申请条件」被路由到项目查询，
答成了项目招生介绍。改成 c_project_query 只负责「有哪些项目/读几年/学什么」，
申请条件、材料、签证、费用归 c_faq。改完路由正确，答案变成高考分数/雅思/申请时间线。

模糊问题仍直接按德国回答（检索首位是德国政策）。指定国家的问句不受影响。
